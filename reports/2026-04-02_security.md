## 外部脅威情報（Geminiより）

本システム（Python / GitHub Actions / Vercel / Anthropic・Google AI API使用）に関連するリスクを以下に抽出・整理します。

### 🔴 高関連リスク

#### 1. GitHub Actions — CVE-2026-31900（Black / `use_pyproject`）
- **概要**: `pull_request_target` トリガーを使用したWorkflowで、外部PRによる `pyproject.toml` 改ざんを通じ、Workflowコンテキストで任意コード実行が可能。GitHub Secretsが漏洩するリスク。
- **本システムへの影響**: `ANTHROPIC_API_KEY` / `GEMINI_API` が窃取される可能性。
- **推奨対応**: Workflowが `pull_request_target` を使用している場合は即刻見直し。Blackをバージョン26.3.0以上に更新。

#### 2. CVE-2026-3644（Python `http.cookies` — Cookie/HTTPヘッダーインジェクション）
- **概要**: `http.cookies` の `Morsel.update()` 等が制御文字（`\r`/`\n`）を拒否せず、HTTPレスポンス分割・Cookieインジェクション・スクリプトインジェクションが可能。
- **本システムへの影響**: Vercel Serverless関数内でCookie操作を行っている場合、攻撃者による不正Cookie注入のリスク。
- **推奨対応**: 該当Pythonバージョンのパッチ適用確認。Cookie値のサニタイズ処理を明示的に実装。

#### 3. CVE-2026-1299（CPython `email` — ヘッダーインジェクション）
- **概要**: `email` モジュールが改行文字を適切に引用しないため、メールヘッダーインジェクションが可能。
- **本システムへの影響**: 通知メール送信機能がある場合に該当。CPythonの最新パッチ確認が必要。

#### 4. CVE-2026-23864 / CVE-2026-27980（Vercel Next.js — DoS脆弱性）
- **概要**: React Server ComponentsへのServer Functionエンドポイント悪用でサーバークラッシュ・メモリ枯渇が可能。React 19.0.4以降・Next.js 15.0.8以降で修正済み。
- **本システムへの影響**: Next.jsを使用している場合、サービス可用性に直接影響。
- **推奨対応**: Next.jsバージョンを15.0.8以降（または16.1.7以降）に更新。

#### 5. CVE-2026-27978（Next.js — Server Action CSRF `origin: null` バイパス）
- **概要**: `origin: null` がCSRF検証をバイパスし、サンドボックス化iframeからServer Actionが呼び出し可能。バージョン16.1.7で修正。
- **本システムへの影響**: Vercel上のServer Actionを持つ機能が対象。APIエンドポイントへの不正リクエストリスク。

#### 6. AI API Token漏洩リスク（全般）
- **概要**: LLMハイジャック攻撃・システムプロンプトインジェクションによるAPIキー漏洩が2025〜2026年で急増。GitHubへのハードコードが最多流出経路。
- **本システムへの影響**: `ANTHROPIC_API_KEY` / `GEMINI_API` が流出した場合、高額課金・不正利用のリスク。
- **現状評価**: 環境変数管理により現時点のリスクは低位。ただし継続的な監視が必要。

#### 7. サプライチェーン攻撃（LiteLLM等PyPIマルウェア）
- **概要**: AIライブラリを偽装したPyPIパッケージがSSHキー・APIキーを窃取。
- **本システムへの影響**: `requirements.txt` / `pyproject.toml` 経由で悪意あるパッケージを導入するリスク。
- **推奨対応**: 依存パッケージのハッシュ固定（`pip install --require-hashes`）・定期的な `pip audit` の実施。

## 推奨事項

### 🛡️ 短期（〜1週間）

1. **依存関係の固定とスキャン自動化**
   - `pip audit` または `safety check` をGitHub Actionsのパイプラインに組み込み、毎コミット時に脆弱性スキャンを自動実行する。
   - `requirements.txt` にハッシュを付与し、PyPIサプライチェーン攻撃を緩和する。

2. **GitHub Actions Workflowの最小権限原則の徹底**
   - `permissions:` ブロックを全Workflowに明示し、`contents: read` など必要最小限に制限する。
   - `pull_request_target` を使用しているWorkflowがあれば、`pull_request` への変更または信頼できるコード以外をチェックアウトしないよう修正する。

3. **Next.js / Reactのバージョン確認と即時アップデート**
   - 本番環境のNext.jsバージョンを確認し、CVE対応済みバージョンへ更新する。

### 🛡️ 中期（〜1ヶ月）

4. **APIキーのローテーション計画策定**
   - `ANTHROPIC_API_KEY` / `GEMINI_API` の定期ローテーション（推奨: 90日ごと）をポリシーとして策定する。
   - GitGuardianや `truffleHog` を導入し、コミット時のシークレットスキャンを自動化する。

5. **Vercel Serverless関数のセキュリティレビュー**
   - `api/claude.js` / `api/gemini.js` において、レスポンスヘッダーへのAPIキー混入・ログ出力の有無を再確認する。
   - レートリミット・リクエスト認証（JWTまたはセッション検証）が実装されているか検証する。

6. **SNS型投資詐欺・フィッシング対策（ユーザー保護）**
   - 本システムが投資関連情報を扱う場合、ユーザーへの注意喚起バナー（「当サービスは投資勧誘を行いません」等）を表示することを検討する。
   - ログインフロー・重要操作にMFA（多要素認証）を実装・推奨する。

### 🛡️ 長期（〜3ヶ月）

7. **SBOM（ソフトウェア部品表）の整備**
   - 使用ライブラリ・バージョンの一覧をSBOMとして管理し、新規CVE発生時に即座に影響範囲を特定できる体制を構築する。

8. **AIプロンプトインジェクション対策**
   - Claude / Gemini APIへのユーザー入力を仲介する場合、プロンプトインジェクション対策（入力サニタイズ・システムプロンプトの分離設計）を実施する。
   - OWASP LLM Top 10（LLM01: Prompt Injection、LLM02: Sensitive Information Disclosure）に基づくセキュリティレビューを実施する。
