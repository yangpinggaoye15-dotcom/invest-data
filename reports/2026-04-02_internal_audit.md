## エグゼクティブサマリー

1. **銘柄選定・仮説チームのKPI構造的未達成が最重要課題**：スクリーニングゼロ件という市場環境に起因するが、`stock_count`（目標5銘柄以上）・`a_rank_win_rate`・`rs_retention`・`reason_quality` の4KPIが全て評価不能または未達成。市場がDefend局面の日にKPI計測が機能しない設計上の欠陥が露呈しており、**KPI定義の見直しが急務**。

2. **レポート統括の`[事実]/[AI分析]ラベル`未遵守が継続リスク**：本日の統括レポートを精査したところ、複数セクション（指数動向テーブル・センチメント指標等）にラベル記載が確認できない。過去レポート（3/28分）でも同様の傾向が見られ、**構造的なコンプライアンス違反**として扱う必要がある。

3. **情報収集チームのマザーズ・日本10年債・出来高急増データ欠落が連鎖的な品質低下を引き起こしている**：`info_coverage` が必須8項目のうち少なくとも2項目で「取得不可」となっており、下流チーム（銘柄選定・投資戦略）のRS上位銘柄分析・セクター分析に直接影響。**データソース拡充が最優先インフラ課題**。

## 改善提案

### 優先度: 高（KPI未達成に直結）

---

**[高-1] KPI定義の市場フェーズ条件分岐導入**

**対象チーム：** 銘柄選定・仮説チーム、投資戦略チーム、内部監査チーム（KPI設計者）

**問題：** `stock_count`（5銘柄以上）・`rr_ratio`（3.0以上）・`plan_concreteness` は、市場フェーズが「Defend」の日には計測値がゼロまたはN/Aになることが構造的に確定している。現行定義では毎回❌が記録されるが、これは**判断品質の問題ではなく定義の問題**であり、改善インセンティブを歪める。

**改善案：**
```
条件分岐KPI定義（案）
- Attack/Steady局面: stock_count ≥ 5銘柄 → 従来通り
- Defend局面: 
  ・ウォッチリスト候補の記録数 ≥ 3件（RS維持銘柄の仮登録）
  ・「段階的エントリー条件」の文書化 ≥ 1件
  ・前Steady局面からのRS低下除外銘柄の記録 ≥ 1件
  を代替KPIとして評価
```

**期待効果：** Defend局面でも各チームに具体的アウトプット目標が与えられ、次のAttack局面への準備品質が向上する。

---

**[高-2] `[事実]/[AI分析]`ラベル自動チェック機構の導入**

**対象チーム：** レポート統括、セキュリティチーム（実装担当）

**問題：** `fact_ai_label` KPIの目標は100%遵守だが、本日の統括レポートで複数セクションの未付与が確認された。過去レポート（3/28分）でも同様の傾向が見られ、**手動チェックのみでは遵守できていない**ことが実証されている。

**改善案：**
```python
# レポート品質チェックスクリプト（概念実装）
def check_fact_ai_labels(report_text: str) -> dict:
    sections = extract_sections(report_text)  # ## 見出しで分割
    unlabeled = []
    for section in sections:
        if not re.search(r'\[事実\]|\[AI分析\]', section.content):
            unlabeled.append(section.title)
    return {
        "compliance_rate": (len(sections) - len(unlabeled)) / len(sections),
        "unlabeled_sections": unlabeled
    }
# run_teams.py の統括レポート生成後に自動実行し、
# 未付与セクションがある場合は警告としてレポート冒頭に挿入
```

**期待効果：** ラベル遵守率を手動0→自動チェック付きで90%以上に向上。`fact_ai_label` KPIの実質的な機能開始。

**[高-3] シミュレーション追跡・検証チームの最低稼働基準の設定と強制レポート化**

**対象チーム：** シミュレーション追跡・検証チーム

**問題：** 本日、同チームのレポートが提出されていない。`kpi_check`（毎日kpi_log.jsonへの記録）・`feedback_count`（週1件以上）のKPIが計測不能な状態が継続している。追跡対象銘柄がゼロでも、以下は実施可能であり、実施すべきである。

**改善案：**
```markdown
## シミュレーション追跡・検証チーム【最低稼働チェックリスト】
銘柄追跡対象ゼロ日でも必須実施項目：
□ kpi_log.jsonに当日分のエントリー記録（空リストでも日付・フェーズは記録）
□ 過去追跡終了シミュレーションの差異分析が未完了の場合はその進捗記録
□ 他チームへの週次フィードバック枠（未発行の場合は「発行予定日」を明記）
□ 翌日の追跡開始候補銘柄の条件整理（Defend解除後のウォッチ対象）
```

**期待効果：** 銘柄ゼロ日でもPDCAが回り続け、Attack局面移行時の即応性が向上する。

### 優先度: 中（品質向上）

---

**[中-1] 情報収集チームのデータソース多様化とfallback機構の整備**

**対象チーム：** 情報収集チーム

**問題：** マザーズ（グロース250）・日本10年債利回り・RS上位銘柄データがGemini単一ソースで安定取得できておらず、`info_coverage`が75%止まりとなっている。これが銘柄選定チームのRS分析不能に直結している連鎖構造を形成している。

**改善案：**
- マザーズ/グロース250終値：Yahoo Finance Japan APIまたはJ-Quants APIをfallbackとして登録
- 日本10年債利回り：日本銀行統計データ公開ページの自動スクレイピングを補助ソースとして追加
- RS上位
